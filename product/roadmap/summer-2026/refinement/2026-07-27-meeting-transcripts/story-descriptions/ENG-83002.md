## Description (paste-ready)

Per ENG-82991 (Functional & UI Changes for AI-Powered 1:1s). This story builds the admin-facing Integrations-page UI for enabling and authenticating the org-level Zoom connection, under **Admin → Platform Configuration → Integrations → Third-Party**.

The Zoom connection is **org-level and one-time**: an admin enables and authenticates Zoom once for the entire org. Individual users are never sent through a Zoom OAuth redirect — per-user permission is handled separately by the consent flow (ENG-82994). This page is the org (level 1) precondition of the consent model: user- and series-level consent cannot occur until the org Zoom connection is authenticated here.

Zoom is listed as a **Collaboration**-category integration with the card copy: *"Enables employees to automatically fetch meeting transcripts from Zoom. Transcripts can be viewed directly or used to power AI-generated meeting prep, action items, agenda topics, and recommendations."*

**Acceptance Criteria**

1. **Card placement** — *Given* an admin is on Platform Configuration → Integrations → Third-Party, *Then* Zoom appears as an integration card under the Collaboration category with the copy above, in the **Not Enabled** group while unconnected.
2. **Enable toggle** — *Given* Zoom is Not Enabled, *When* the admin turns on *Enable this integration*, *Then* the **AUTHENTICATE** action becomes available on the card.
3. **Authenticate redirect** — *Given* the integration is enabled but not yet authenticated, *When* the admin clicks AUTHENTICATE, *Then* they are redirected to the Zoom OAuth authorization page.
4. **Success toast + enabled state** — *Given* the admin completes Zoom OAuth authorization, *When* they are redirected back to Betterworks, *Then* a success toast confirms the connection, *And* the Zoom card moves to the **Enabled** group.
5. **Connection status** — *Given* Zoom is connected, *Then* the card shows a connected state consistent with other enabled integrations (e.g. last-sync/connection timestamp).
6. **Cancelled or failed auth** — *Given* the admin cancels or authorization fails at Zoom, *When* they return to Betterworks, *Then* the connection is not established, Zoom remains Not Enabled, *And* a non-blocking error state is shown. *(Error copy — see Open Questions.)*
7. **Org-scope, no per-user redirect** — *Given* the org Zoom connection is authenticated, *Then* no individual user is ever prompted with a Zoom OAuth redirect; user permission is captured by the consent flow (ENG-82994).
8. **Disconnect** — *Given* Zoom is Enabled, *When* the admin disables the integration, *Then* the org connection is revoked, *And* dependent user consent records transition to paused (handled by ENG-82994) rather than being deleted.
