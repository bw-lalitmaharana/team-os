## Description (paste-ready)

Per ENG-82991. UI for **all AI suggestions and completions** on the 1:1 meeting page. This ticket renders recommendations produced by the AI platform (ENG-82387) — **no generation, dedup, or entity-ID logic here**. Suggestions come in two types: **create** (suggested agenda topic, suggested action item, Create-Goal recommendation) and **update-close** (items the AI detects were covered/completed). Meetings pod owns rendering and interaction; the AI pod owns generation, deduplication, and the entity IDs used for grouping. Accept and dismiss actions are recorded per recommendation for acknowledgment analytics.

Placement: an "N AI suggestions below" pill sits on the Agenda Topics and Action Items sections; suggested items render below user-added items and above the +Add input; completion ("covered") cards render within the relevant section.

**Acceptance Criteria**

*Suggested agenda topics (create)*
1. **Render** — *Given* AI suggested agenda topics exist for an Upcoming or Active meeting, *Then* they render below user-added topics and above the +Add input as a distinct type with an AI badge, under a "N AI suggestions below" pill.
2. **Evidence** — *Given* a suggested topic, *Then* it shows a citation/evidence line ("Based on discussions from [date]").
3. **Add** — *When* the user taps +ADD, *Then* the topic promotes to a user-added agenda topic; *And* the AI badge is removed and the text becomes editable.
4. **Dismiss** — *When* the user taps ✕, *Then* the suggestion is removed immediately, does not reappear on reload, *And* the dismissal is recorded to the AI platform.

*Suggested action items (create)*
5. **Render** — *Given* AI suggested action items exist, *Then* they render below user-added action items with an AI badge under the "N AI suggestions below" pill; *And* each shows suggested text, an evidence sub-line, and the attributed person where identified.
6. **Add** — *When* the user taps +ADD, *Then* the item becomes a standard action item with pre-filled text/person, editable inline, with no side panel.
7. **Dismiss** — *When* the user taps ✕, *Then* the suggestion is removed and the dismissal recorded.

*Create-Goal recommendation (create, special)*
8. **Render** — *Given* a Create-Goal recommendation, *Then* it renders as an action-item suggestion with both a **CREATE GOAL** and an **+ADD** action plus a rationale sub-line.
9. **Create goal** — *When* the user taps CREATE GOAL, *Then* the goal-creation form opens auto-populated from the recommendation (inline form, platform-wide API); *And* the suggestion persists until added or dismissed.
10. **Add as action item** — *When* the user taps +ADD, *Then* the recommendation is added as a standard action item instead.
11. **Dismiss** — *When* the user taps ✕, *Then* the recommendation is removed and the dismissal recorded.

*Completions — covered items (update-close)*
12. **Covered agenda topics card** — *Given* the AI detects agenda topics that appear covered, *Then* a card renders in the Agenda Topics section — "AI identified N agenda topic(s) that appear to have been covered" — listing them with green checks, with **MARK SUGGESTED ITEMS DONE** and a dismiss (✕).
13. **Covered action items card** — *Given* the AI detects action items that appear covered, *Then* the same card pattern renders in the Action Items section.
14. **Mark done** — *When* the user taps MARK SUGGESTED ITEMS DONE, *Then* the listed items are marked complete.
15. **Dismiss card** — *When* the user taps ✕, *Then* the card closes without changing item status; *And* the dismissed coverage suggestion is not re-shown.

*Grouping, acknowledgment, lifecycle*
16. **Grouping** — *Given* suggestions with entity IDs, *Then* the UI groups them by type (create vs update-close) as supplied; *And* the Meetings pod does not re-deduplicate.
17. **Acknowledgment** — *Given* any suggestion, *When* it is accepted (add / create goal / mark done) or dismissed, *Then* the action is recorded per recommendation for analytics.
18. **Expiry** — *Given* the meeting transitions to Completed, *Then* the suggestion and completion surfaces expire silently, with no expiry message.
19. **No suggestion chrome** — *Given* generation is in progress, *Then* no skeleton is shown for suggestions; *Given* none are generated, *Then* no empty state is shown (sections show user content only); *Given* generation fails, *Then* it is silent — no error shown.
